WristCommand LTE 준비WristCommand LTE setup

WristCommand LTE는 본인 개발자 계정의 무료 사용량으로 인터넷(폰 경유) 명령을 쓰는 앱입니다. 처음 한 번 약 30분 준비가 필요하고(개발자 앱 승인 대기는 빼고), 폰만으로 할 수 있습니다. 아래 카드를 위에서부터 하나씩 하세요. 초록 단추 [열기]는 그 화면을 새 탭으로 엽니다 — 이 페이지는 닫지 말고 탭만 오가세요. 파란 [복사]를 누른 뒤 그 화면의 칸에 붙여넣으면 됩니다. 직접 입력하는 곳은 계정 가입·로그인, 2번 GitHub 아이디, 1번 인증 앱 번호, 8번 개발자 사이트 첫 본인 정보뿐입니다.

WristCommand LTE uses your own developer account's free usage for remote (phone) commands. The one-time setup takes about 30 minutes plus the wait for developer app approval, and can be done on a phone. Go through the cards from the top. Green [Open] opens that screen in a new tab — keep this page open and switch tabs. Tap blue [Copy], then paste into the field on that screen. You only type for account sign-up and sign-in, your GitHub username (card 2), the authenticator code (card 1) and your first-time details on the developer site (card 8).

이 페이지는 입력한 값을 인터넷으로 보내지 않습니다(7번 [게시 확인]은 내 공개키 주소를 읽어 오기만 합니다). 입력한 값은 이 화면과 클립보드에만 있습니다(GitHub 아이디만 이 폰에 기억). 개발자 계정에 결제수단은 넣지 마세요 — 이 앱은 무료 사용량 안에서만 쓰도록 만들었고, 무료 사용량을 다 쓰면 그달 남은 기간은 블루투스로만 씁니다.

This page never sends what you type over the internet ([Check] in card 7 only reads your public key address). What you type stays on this screen and in your clipboard (only your GitHub username is remembered on this phone). Do not add a payment method to the developer account; the app is built to stay within the free usage, and once that runs out it uses Bluetooth for the rest of the month.

1차 계정 2단계 인증 켜기Turn on two-factor authentication on your car account

개발자 사이트 가입 조건입니다(이메일 인증 + 2단계 인증).

The developer program requires a verified email and multi-factor authentication.

열기 · 차 계정 보안 설정Open · Car account security settings
  1. 폰에 인증 앱(Google Authenticator·Microsoft Authenticator 등)이 없으면 먼저 설치합니다.
  2. If your phone has no authenticator app (Google Authenticator, Microsoft Authenticator, etc.), install one first.
  3. 열린 「보안」 화면(로그인을 물으면 차 계정으로 로그인)에서 「추가 보안 인증」(Multi-Factor Authentication) 옆이 「등록됨」이면 이 카드는 끝입니다.
  4. On the Security screen that opens (sign in with your car account if asked): if Multi-Factor Authentication already shows as registered, this card is done.
  5. 아니면 그 옆 단추(Set Up) → 「다음」(Next) → 인증 앱에 차 계정을 추가합니다: 그림 코드(QR)가 보이면 인증 앱으로 찍고, 폰 한 대로 하느라 찍을 수 없으면 Set up manually를 눌러 나오는 키를 복사해 인증 앱의 새 계정에 붙여넣습니다(제조사 지원 문서의 두 방법).
  6. Otherwise tap the button next to it (Set Up) → Next → add your car account to the authenticator app: if a QR code is shown, scan it with the app; if you can't (doing it all on one phone), tap Set up manually, copy the key shown and paste it into a new account in the app (the two methods in the support article).
  7. 인증 앱이 보여 주는 6자리 번호를 그 화면에 넣습니다 → Get New Passcodes로 예비 번호를 받아 저장해 둡니다(인증 앱을 잃었을 때 씁니다).
  8. Enter the 6-digit code the app shows → tap Get New Passcodes and save the backup passcodes (for when you lose the app).

4공개키 만들기 (이 페이지에서)Make the public key (on this page)

비밀 키는 이 브라우저 안에서만 잠깐 생겼다가 페이지를 닫으면 사라지고, 꺼낼 수도 없습니다. 시계는 이 키를 쓰지 않습니다(명령은 시계 키로 서명합니다). 주소마다 다른 키가 필요해서 만드는 것입니다. 다음 카드를 마치기 전에 이 페이지를 닫으면 다시 만드세요.

The private half exists only inside this browser, cannot be exported, and is gone when you close the page. The watch never uses it (commands are signed with the watch key); every address just needs its own key. If you close this page before finishing the next card, make it again.

5공개키 파일 올리기Upload the public key file

열기 · 공개키 파일 (이름·내용 채워짐)Open · Public key file (name and content filled in)

단추가 흐리면 2번 아이디와 4번 공개키를 먼저 하세요.

If the button is greyed out, do card 2 (username) and card 4 (public key) first.

  1. 열린 화면 위쪽 경로가 .well-known / appspecific /, 파일 이름 칸이 com.tesla.3p.public-key.pem, 내용이 -----BEGIN PUBLIC KEY-----로 시작하는 4줄인지 봅니다(채워져 있습니다).
  2. On the screen that opens, check the path at the top is .well-known / appspecific /, the file name field is com.tesla.3p.public-key.pem and the content is four lines starting with -----BEGIN PUBLIC KEY----- (all filled in).
  3. 초록 Commit changes... → 뜨는 창에서 Commit directly to the main branch가 골라진 그대로 두고 Commit changes.
  4. Green Commit changes... → in the dialog, leave Commit directly to the main branch selected and tap Commit changes.

GitHub 앱이 열리고 칸이 비어 있으면 [열기]를 길게 눌러 브라우저(사파리·크롬)로 여세요. 칸이 비어 있거나 화면이 안 열리면(이미 있던 저장소라 기본 가지가 main이 아닐 때 등) 예비 방법: 내 저장소 열기 → Add file → Create new file → 파일 이름 → 이름 칸에 붙여넣기 → 공개키 → 내용 칸에 붙여넣기 → Commit changes... → Commit changes.

If the GitHub app opens with empty fields, long-press [Open] and open it in the browser (Safari or Chrome). If the fields are empty or the screen doesn't open (e.g. an existing repository whose default branch isn't main), backup steps: open your repository → Add file → Create new file → file name → paste into the name field → public key → paste into the content box → Commit changes... → Commit changes.

6점 폴더 보이게 하기 (.nojekyll)Let the dot-folder be served (.nojekyll)

열기 · .nojekyll 파일 (이름·내용 채워짐)Open · .nojekyll file (name and content filled in)
  1. 파일 이름이 .nojekyll인지 봅니다 → Commit changes... → Commit changes.
  2. Check the file name is .nojekyll → Commit changes... → Commit changes.

점(.)으로 시작하는 폴더를 웹에 보이게 하는 파일입니다(내용은 상관없습니다). 칸이 비어 있거나 화면이 안 열리면 5번과 같은 예비 방법(내 저장소 → Add file → Create new file)으로 파일 이름 → 이름 칸에 붙여넣기 → 내용 → 내용 칸에 붙여넣기 → 커밋. 이미 이 저장소로 블로그 같은 사이트를 쓰고 있다면 .nojekyll 대신 _config.yml 에 include: [".well-known"] 한 줄을 더하세요 — .nojekyll 을 넣으면 그 사이트가 꺼질 수 있습니다.

This file lets folders starting with a dot be served (its content does not matter). If the field is empty or the screen doesn't open, use the same backup steps as card 5 (your repository → Add file → Create new file): file name → paste into the name field → content → paste into the content box → commit. If this repository already hosts a site (e.g. a blog), add the line include: [".well-known"] to _config.yml instead; .nojekyll could switch that site off.

7웹 게시 확인Check publishing

아이디.github.io 저장소는 따로 켜지 않아도 자동으로 게시됩니다. 5·6번을 마치고 몇 분(최대 10분) 뒤 아래 단추를 누르세요.

A username.github.io repository is published automatically. A few minutes (up to 10) after cards 5 and 6, tap the button below.

10분이 지나도 「아직」이면 게시 설정 화면을 열어 Build and deployment의 Source가 Deploy from a branch, 가지는 파일을 올린 가지(새로 만든 저장소면 main), 폴더 / (root)인지 봅니다. 아니면 그렇게 고르고 Save. 단 이미 이 저장소로 블로그 같은 사이트를 쓰고 있다면 게시 설정은 바꾸지 말고, 지금 설정된 가지·폴더(또는 GitHub Actions)에 공개키 파일이 들어가게 올리세요 — 설정을 바꾸면 그 사이트가 꺼질 수 있습니다.

If it still says “not yet” after 10 minutes, open the publishing settings and make sure, under Build and deployment, that Source is Deploy from a branch, the branch is the one you committed to (main for a new repository), folder / (root). If not, pick them and tap Save. But if this repository already hosts a site (e.g. a blog), don't change the publishing settings; put the key file where the current branch and folder (or GitHub Actions) publish from — changing the settings could switch that site off.

단추로 확인이 안 되면 내 공개키 주소를 직접 여세요. 글자가 보이거나 파일로 내려받아지면 게시된 것입니다.

If the button can't check it, open your public key address directly. If you see the text or the file downloads, it is published.

내 도메인을 쓰는 경우 3·5·6 카드 대신, 그 사이트의 같은 경로(/.well-known/appspecific/com.tesla.3p.public-key.pem)에 4번 공개키를 올리고 7번에서 확인하세요.If you use your own domain, skip cards 3, 5 and 6: put the key from card 4 at the same path (/.well-known/appspecific/com.tesla.3p.public-key.pem) on that site and check it in card 7.
